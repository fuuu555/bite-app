# 觀光署重複管理與地圖資料來源實作計畫

## 工作範圍

依據 `docs/superpowers/specs/2026-10-03-tourism-duplicate-management-and-map-sources-design.md`，完成觀光署疑似重複清單、可還原忽略、地圖兩種來源獨立開關，以及中原大學測試店一次性種子資料。

## 步驟

1. **資料模型與 migration**
   - 為 `tourism_source_places` 新增忽略欄位與名稱 trigram 索引。
   - 新 clone 初始化時以穩定識別值新增中原大學測試店；以相同名稱與地址防止既有資料庫重複，分類使用 `taiwanese` slug，Google 自動搜尋預設關閉。
2. **後端觀光資料流程**
   - 新增疑似重複候選查詢，使用名稱正規化、`pg_trgm` 與地址／座標佐證，分頁回傳比對理由。
   - 新增忽略與還原操作；一般管理列表及公開地圖排除忽略資料；匯入 upsert 保留忽略狀態。
3. **觀光資料管理 UI**
   - 在既有名稱／地址搜尋旁提供疑似重複檢視與已忽略檢視。
   - 顯示成對比對、來源資料集與命中原因；支援忽略與還原並明確提示不影響 BiteMap 店家。
4. **地圖來源控制**
   - `MapFilters` 改為 `showBiteMapRestaurants` 與 `showTourismData` 兩個獨立狀態，預設皆開啟。
   - 移除 `officialOnly` 行為；每個來源關閉時停止該來源的新查詢並隱藏地圖圖層；同步篩選數、標籤、清除與空結果提示。
5. **驗證**
   - 增加後端比對、忽略／還原、重複匯入及公開查詢測試。
   - 增加前端來源開關預設、獨立切換、略過查詢、篩選摘要與清除測試。
   - 執行相關前後端測試、lint、typecheck；檢查 migration SQL 及 dirty worktree，確保不包含無關修改。

## 完成條件

- 相似店名的觀光署資料會以候選方式列出，由管理員判斷，不會自動合併。
- 忽略資料在列表及地圖隱藏，重複匯入不會復活，可還原；連結 BiteMap 店家不受影響。
- BiteMap 店家與觀光署圖層可單獨開關；原「觀光署推薦」篩選移除。
- 新 clone migration 建立測試店；已存在資料不重複建立，管理員刪除後不因 app restart 重建。
