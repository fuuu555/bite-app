# Stage 2 公開地圖 MVP 設計規格

日期：2026-09-20

## 1. 目標與範圍

Stage 2 完成 BiteMap 第一個一般使用者可操作的產品頁面。使用者可以從 `/map` 查看資料庫中已發布的附近店家，允許或拒絕定位，移動地圖後主動搜尋目前區域，並開啟單店預覽卡。

本階段同時建立使用者端共用 Footer 與五個主要入口：探索、地圖、約飯、聊天室、個人。尚未開發的入口使用獨立準備中頁面，不用假資料模擬完成狀態。

一般使用者登入與 Google 登入不納入本階段，依既定計畫留在 Stage 5。店家群聚與完整篩選 UI 留在 Stage 3。

## 2. 路由與資訊架構

| 路由                | 用途           | Stage 2 狀態                                     |
| ------------------- | -------------- | ------------------------------------------------ |
| `/`                 | 使用者探索首頁 | 最小首頁：BiteMap 說明、探索準備中、開啟地圖按鈕 |
| `/map`              | 公開店家地圖   | Stage 2 主要完成頁面                             |
| `/meals`            | 約飯           | 準備中頁面                                       |
| `/chat`             | 聊天室         | 準備中頁面                                       |
| `/profile`          | 個人頁面       | 準備中頁面                                       |
| `/restaurants/{id}` | 餐廳詳細頁     | Stage 2 暫時準備中，保留店家識別值               |

首頁不得自行加入推薦排序、餐廳列表或其他尚未確認的探索功能。完整首頁內容仍依 `FUNCTIONAL_REQUIREMENTS.md` 保持未決定。

## 3. 共用使用者 App Shell

使用者頁面共用五功能 Footer：

| 順序 | 顯示名稱 | 路由       | 圖示語意   |
| ---- | -------- | ---------- | ---------- |
| 1    | 探索     | `/`        | 指南針     |
| 2    | 地圖     | `/map`     | 地圖       |
| 3    | 約飯     | `/meals`   | 使用者群組 |
| 4    | 聊天室   | `/chat`    | 對話框     |
| 5    | 個人     | `/profile` | 使用者     |

Footer 在手機與桌面都位於畫面底部。手機版固定滿寬；桌面版內容置中並限制最大寬度，但不改成管理後台側邊欄。每個項目同時顯示 Tabler icon 與繁體中文文字。當前頁使用珊瑚橘圖示、深色文字與上方短線，避免只靠顏色標示狀態。

Footer 必須保留足夠觸控範圍、鍵盤焦點樣式、`aria-current="page"` 與安全區域 padding。

## 4. 公開地圖頁

### 4.1 版面

`/map` 使用地圖優先的全畫面操作模式。地圖高度使用動態 viewport 單位，扣除 Footer 後填滿剩餘空間。

- 左上：目前區域資訊；不額外顯示獨立品牌卡，避免遮擋地圖內容。
- 上方中央：地圖移動後出現的「搜尋此區域」。
- 右側：回到目前位置按鈕。
- 地圖畫布：MapLibre GL JS 搭配 OpenFreeMap 2D style。
- 地圖標記：主要料理分類顏色加料理圖示。
- 下方：店家預覽卡，位於 Footer 上方。

手機預覽卡由底部進出；桌面預覽卡位於左下方並限制寬度。動效只用於狀態轉換與操作回饋，且遵守 `prefers-reduced-motion`。

### 4.2 初始位置

進入地圖後依序使用：

1. 使用者允許的瀏覽器目前位置。
2. 瀏覽器中保存的上次地圖中心與縮放層級。
3. 桃園中壢預設中心。

定位拒絕、失敗或逾時不阻斷地圖使用，也不得覆蓋既有位置紀錄。使用者完成「搜尋此區域」後，保存當下地圖中心與縮放層級，供下次進入時使用。

### 4.3 地圖查詢行為

首次完成地圖初始化後，以目前可視範圍查詢店家。使用者拖曳或縮放時，不自動呼叫 API，只顯示「搜尋此區域」。使用者點擊後才以最新 bounds 與 zoom 查詢。

查詢期間保留舊標記並顯示載入狀態。成功取得新資料後才一次替換地圖來源；失敗時維持舊標記。

點擊單店標記後開啟預覽卡，至少顯示：

- 餐廳名稱。
- 主要料理分類名稱與圖示。
- 價格區間。
- 前往餐廳頁面的操作。

預覽卡點擊後前往 `/restaurants/{id}`。本階段餐廳頁為準備中頁面，不虛構餐廳詳細內容。

## 5. 後端與 API

公開端點：

```http
GET /api/v1/map/restaurants
    ?west={longitude}
    &south={latitude}
    &east={longitude}
    &north={latitude}
    &zoom={level}
    &cuisine_ids={optional_ids}
    &price_ranges={optional_ranges}
```

所有邊界、縮放層級與篩選值都必須在 API 驗證。API 不允許省略地圖邊界後取得全部店家。

PostGIS 查詢只選取：

- `restaurants.status = 'published'`。
- 具有有效座標的店家。
- 位於目前 bounds 內的店家。
- 符合可選料理分類與價格條件的店家。

最小回傳資料：

- 店家 ID、名稱。
- 經緯度。
- 主要料理分類 ID、顯示名稱、色票與圖示鍵值。
- 價格區間。
- 可選菜單網址。

API 設定安全結果上限。超過上限時回傳可辨識的 `zoom_required` 狀態，不截斷成看似完整的結果，也不將整個資料庫傳給瀏覽器。

## 6. 元件與責任邊界

| 元件／模組                 | 責任                                              |
| -------------------------- | ------------------------------------------------- |
| `UserAppShell`             | 使用者頁面的內容區與共用 Footer                   |
| `UserFooterNav`            | 五個入口、當前路由、鍵盤與無障礙狀態              |
| `PublicMapPage`            | 組合地圖頁狀態，不直接處理 MapLibre 細節          |
| `PublicMapCanvas`          | 初始化與銷毀 MapLibre、bounds、zoom、marker click |
| `MapSearchAreaButton`      | 地圖移動後的明確搜尋操作與載入狀態                |
| `MapLocationControl`       | 定位請求、成功／拒絕／逾時狀態                    |
| `RestaurantPreviewCard`    | 顯示選取店家的最小預覽與詳細頁連結                |
| `public-map-api`           | 組合查詢參數、解析回應與統一錯誤型別              |
| FastAPI map router/service | 驗證輸入、PostGIS bounds 查詢與結果上限           |

互動元件維持為小型 Client Components；靜態頁面骨架與準備中內容優先使用 Server Components。

## 7. 視覺系統

此頁面延伸現有 BiteMap 品牌，不重設管理後台或另創第二套設計系統。

- 主題：淺色。
- 背景：暖白與 OpenFreeMap 2D 地圖。
- 文字：深青墨色。
- 主要操作：珊瑚橘。
- 地圖標記：資料庫料理分類色票，同時搭配文字或圖示。
- 圓角、陰影與動效：沿用 `apps/frontend/src/styles/tokens.css`。
- 圖示：使用一致的 Tabler Icons，不使用 emoji 或自行繪製的不一致 SVG。

地圖是視覺主體。介面不得加入假店家照片、裝飾性漸層、大型 Hero、浮誇玻璃效果或與操作無關的卡片。

## 8. 狀態與錯誤處理

| 狀態           | 行為                                         |
| -------------- | -------------------------------------------- |
| 定位拒絕／逾時 | 改用上次位置或桃園中壢，顯示非阻斷提示       |
| 底圖載入失敗   | 保留 App Shell 與 Footer，提供重試按鈕       |
| API 查詢中     | 保留舊標記並顯示載入回饋                     |
| API 查詢失敗   | 保留舊標記，提供非阻斷錯誤與重試操作         |
| 查無店家       | 保持目前地圖位置，顯示此區域沒有已發布店家   |
| 結果過多       | 提示放大地圖後再搜尋，不清空舊結果           |
| 店家座標異常   | 後端略過異常資料並記錄錯誤，不使整批回應失敗 |
| 未完成功能     | 顯示準備中狀態與回首頁／開啟地圖操作         |

## 9. 測試策略

### 後端

- PostGIS bounds 內外資料。
- 只回傳 `published` 店家。
- 無座標、草稿與封存店家不回傳。
- 邊界與 zoom 參數驗證。
- 料理分類與價格參數。
- 超過結果上限時回傳 `zoom_required`。

### 前端

- Footer 五入口與當前狀態。
- 定位成功、拒絕與逾時降級。
- 地圖移動不自動查詢。
- 搜尋按鈕使用最新 bounds。
- 查詢期間與失敗後保留舊標記。
- 空資料、結果過多與底圖失敗狀態。
- 標記點擊開啟正確預覽卡。

### E2E

- 從首頁進入公開地圖。
- 拒絕定位後使用桃園中壢。
- 移動地圖並搜尋目前區域。
- 點擊店家標記、查看預覽卡並前往暫時餐廳頁。
- Footer 可進入三個準備中頁面並返回地圖。

測試資料必須透過交易回滾或明確 teardown 清除。測試不得在開發資料庫留下 E2E 使用者、料理分類、店家、Session 或稽核紀錄。

## 10. 驗收條件

- `/` 已成為一般使用者首頁，不再顯示 Stage 0 系統健康卡。
- `/map` 在手機及桌面都能正常顯示 OpenFreeMap 2D 地圖。
- 定位拒絕時仍可從桃園中壢開始使用。
- 公開 API 只回傳 bounds 內的已發布店家。
- 移動地圖後必須由使用者點擊「搜尋此區域」才重新查詢。
- 點擊單店標記會顯示正確的底部預覽卡。
- Footer 顯示五個入口，當前頁狀態清楚且支援鍵盤操作。
- 底圖、定位與 API 失敗都有可理解的降級行為。
- 後端整合測試、前端測試與 Playwright E2E 通過，且不留下測試資料。

## 11. 明確不包含

- 一般使用者帳密、匿名身分或 Google 登入。
- 店家群聚與群聚拆分。
- 完整料理分類與價格篩選 UI。
- 完整探索首頁與推薦排序。
- 完整餐廳詳細頁。
- 約飯、聊天室與個人頁面的正式功能。
- 外部店家爬蟲或未審核店家匯入。
