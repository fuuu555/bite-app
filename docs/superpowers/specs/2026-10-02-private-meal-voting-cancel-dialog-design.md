# 私人約飯投票與解除確認框設計

## 目標

修正兩個已確認的產品行為：

1. 約飯解除操作全部使用 App 內建確認框。
2. 私人約飯建立時可以選擇「集合後投票」，並在申請審核通過後沿用現有投票流程。

## 行為

- 約飯詳細頁與約飯列表中的解除操作共用 `AppConfirmDialog`，確認後才呼叫既有解除 API，取消或按 Escape 不執行操作。
- 私人約飯可在建立視窗選擇投票模式；建立時可帶入第一家候選餐廳。
- 私人約飯仍採申請制，待審核者不能查看候選或票數；成為正式成員後才能查看候選、投票與票數。
- 私人飯局不使用加入截止時間，由發起人管理候選並手動開始投票。

## 實作範圍

- 建立表單：解除私人模式下「集合後投票」的錯誤 disabled 條件。
- 解除操作：移除指定約飯解除流程中的 `window.confirm`，改用共用內建對話框。
- 後端：維持既有私人投票 API 與權限規則，補強建立私人投票模式的整合測試。
- 文件：同步功能需求與開發計畫，標記私人投票已可使用。

## 不在範圍

- 不改資料庫 schema，不新增 migration。
- 不改私人約飯申請、審核、聊天室或 WebSocket 授權規則。
- 不處理其他管理後台的瀏覽器確認框。

## 驗收

- 建立私人約飯時，「集合後投票」可以選取並成功建立。
- 私人約飯申請通過後，發起人可以新增候選並開始投票，正式成員可以投票。
- 約飯解除按鈕顯示 App 內建確認框，取消不會解除，確認才會解除。
- 前端 lint、typecheck、測試、production build 與後端 lint、typecheck、測試通過。
