# 觀光署疑似重複地區篩選與永久刪除設計

## 目標

讓管理員能先用縣市與行政區縮小觀光署疑似重複配對，再明確確認刪除多餘的來源資料。被刪除的來源記錄不得在日後匯入時復活。

## 決策

- 疑似重複檢視沿用名稱／地址搜尋，新增縣市與行政區下拉篩選。行政區選項依所選縣市變更；配對任一側的地址符合所選縣市及行政區時，該配對即納入結果。
- 移除「已忽略」檢視、忽略／還原操作，以及 `is_ignored` 欄位；不再提供軟刪除的管理流程。
- 每組候選的兩筆觀光署記錄各自提供「刪除此筆」操作，操作前顯示確認，明確列出名稱及地址。刪除只作用於選定的觀光署來源記錄，不刪除與其連結的 BiteMap 店家。
- 確認刪除時，在同一資料庫交易內保存最小 tombstone（資料集與官方來源記錄 ID）並刪除來源資料列。匯入時略過 tombstone 中的記錄，避免官方資料重新下載後復活。
- 不提供還原功能；如需重新納入，需透過後續明確管理流程處理 tombstone，而非一般匯入自動恢復。

## 後端與資料庫

- 新 migration 建立官方來源刪除 tombstone 表，唯一鍵為 `(source_dataset, source_record_id)`，並移除上一版增加的 `is_ignored` 欄位。已套用上一版 migration 的資料庫可直接升級；新資料庫亦能順序升級。
- 疑似配對 API 接收 `city`、`district`，計數與分頁查詢均套用相同地區條件。
- 新增管理員專用來源資料刪除端點；找不到來源列回傳 404，成功後回傳明確刪除結果。
- 匯入 upsert 在新增／更新來源資料前檢查 tombstone；已刪除的官方來源 ID 不重新建立。
- 公開地圖與一般管理列表不需額外過濾刪除狀態，因來源列已刪除。

## 管理介面

- 疑似重複檢視呈現縣市、行政區、名稱／地址搜尋條件與成對結果。
- 兩側資料卡分別提供刪除按鈕；確認視窗指出刪除不可由匯入復原、連結 BiteMap 店家會保留。
- 刪除成功後重新載入目前條件與分頁；若候選配對因此消失，顯示成功提示。
- 移除已忽略檢視、忽略／還原按鈕及其文案和狀態。

## 錯誤處理與安全

- 刪除必須由管理員授權；tombstone 寫入與來源列刪除同一交易提交，避免只完成其中一項。
- 匯入時先取已刪除 ID 集合並略過；更新現有記錄不會清除 tombstone。
- 刪除來源列不連帶刪除 `restaurants` 資料；刪除及匯入錯誤回滾交易並回傳可理解訊息。

## 驗證

- 後端測試：地區條件作用於配對任一側、刪除建立 tombstone 並刪除來源列、後續相同來源 ID 匯入不會重建、連結 BiteMap 店家仍存在、不存在 ID 回傳 404。
- 前端驗證：縣市改變時清空行政區、配對地區篩選與關鍵字可並用、刪除確認內容正確、取消不發請求、成功後列表更新；頁面不再出現「已忽略」相關流程。
- Migration 驗證：由 0029 升級後可刪除並抑制來源記錄；乾淨資料庫由基礎版本升級到最新版本成功。
