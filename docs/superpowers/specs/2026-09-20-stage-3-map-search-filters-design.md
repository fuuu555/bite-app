# Stage 3 地圖搜尋與篩選設計規格

日期：2026-09-20
狀態：已由使用者確認，待排入實作

## 1. 目標與範圍

Stage 3 在 Stage 2 公開地圖的基礎上，加入地圖上方搜尋列與條件篩選。使用者可以搜尋地區／地址或已發布店家，也可以依縣市／行政區、價格與料理分類縮小目前地圖結果。

本階段採 B 方案：預設只顯示搜尋列；點擊「篩選」後才展開條件面板。篩選完成後面板收起，條件以標籤保留在搜尋列下方。

本階段仍不做完整探索頁搜尋、排序、評價或推薦；地圖店家搜尋只提供快速定位與預覽卡入口。

## 2. 已確認的使用者流程

### 2.1 搜尋列

搜尋列提示文字為「搜尋地區、地址或店家名稱」。輸入至少 2 個字元後，以約 300ms debounce 查詢下拉結果。

結果分為兩組：

- 地區／地址：顯示地名與行政區。點擊後地圖移動到該位置，顯示「搜尋此區域」，不立即查詢店家。
- 已發布店家：顯示店名、料理分類與價格。點擊後地圖移動到店家、放大至店家層級並開啟預覽卡。

搜尋結果最多顯示 5 筆。按 Enter 時選取第一筆；沒有結果時顯示「找不到地區或已發布店家」，且保留目前地圖。

地區結果由 Geocoding Provider 提供，店家結果只查詢 BiteMap `published` 店家；外部地理編碼結果不能直接成為店家資料。

### 2.2 篩選面板

點擊「篩選」後，在搜尋列下方展開面板，包含：

- 地區：縣市 → 行政區，單選。
- 價格：`$200 以下`、`$200–400`、`$400–800`、`$800 以上`，可複選。
- 料理：後台已啟用的料理分類，可複選。
- 「清除條件」與「套用篩選」。

使用者先調整條件，按「套用篩選」後面板自動收起；條件以標籤保留，例如 `中壢`、`料理：日式`、`$200–400`。套用只更新待查詢狀態，仍須按「搜尋此區域」才送出目前 bounds 查詢。

### 2.3 響應式行為

桌面版搜尋列置中，篩選面板從下方展開；品牌維持左上、定位維持右下。手機版搜尋列位於品牌下方，面板在搜尋列下方展開並可垂直捲動，不使用全螢幕 Modal。條件標籤可水平滑動，且不能遮住 Footer、定位控制或店家預覽卡。

## 3. API 與資料流

### 3.1 搜尋端點

```http
GET /api/v1/map/search?q={query}&limit=5
```

回應分為 `locations` 與 `restaurants`：

```text
locations:
  label, region, latitude, longitude, source
restaurants:
  id, name, latitude, longitude, primary_cuisine, price_range, menu_url
```

後端以服務層分離地理編碼與店家搜尋。地理編碼請求必須經過既有 Provider adapter；店家名稱使用 PostgreSQL 的安全參數查詢，只查 `published` 且名稱／地址符合關鍵字的店家。

### 3.2 地圖端點擴充

既有端點維持可視範圍為必要條件：

```http
GET /api/v1/map/restaurants
    ?west={longitude}
    &south={latitude}
    &east={longitude}
    &north={latitude}
    &zoom={level}
    &city={optional_city}
    &district={optional_district}
    &cuisine_ids={optional_ids}
    &price_ranges={optional_ranges}
```

所有條件由 API 驗證。初期地區條件使用管理員輸入的標準化地址文字做 allowlisted city／district 關鍵字比對，不新增重複的餐廳行政區欄位；未來若資料量或地址品質需要，再以獨立地址／行政區資料模型提出 migration。

### 3.3 前端狀態邊界

- `searchQuery`：搜尋列文字。
- `searchResults`：下拉候選。
- `pendingFilters`：面板內尚未套用的值。
- `activeFilters`：已套用、等待搜尋地圖的值。
- `searchNeeded`：地圖 bounds 或條件改變後是否需要主動搜尋。

搜尋或篩選 API 失敗時保留既有地圖標記。只有成功取得新的地圖結果後才替換標記。

## 4. 錯誤與空狀態

| 狀態           | 行為                                       |
| -------------- | ------------------------------------------ |
| 搜尋 API 失敗  | 下拉顯示可重試訊息，不影響目前地圖         |
| Geocoding 逾時 | 顯示找不到地區，不寫入店家資料             |
| 店家搜尋無結果 | 顯示找不到已發布店家                       |
| 篩選後無結果   | 保留地圖與條件標籤，顯示沒有符合條件的店家 |
| 結果過多       | 沿用 `zoom_required`，提示放大地圖         |
| 查詢進行中     | 保留舊標記並顯示載入狀態                   |

## 5. 元件責任

| 元件／模組             | 責任                                       |
| ---------------------- | ------------------------------------------ |
| `MapSearchBar`         | 輸入、debounce、清除與鍵盤選取             |
| `MapSearchResults`     | 分組顯示地區與店家候選                     |
| `MapFilterPopover`     | 暫存地區、價格、料理條件與套用／清除       |
| `MapActiveFilterChips` | 顯示已套用條件並提供單項移除               |
| `map-search-api`       | 呼叫搜尋端點與統一錯誤型別                 |
| `map_service`          | 店家關鍵字、地區、價格、料理與 bounds 查詢 |
| `geocoding`            | 只處理外部地址／座標轉換                   |

## 6. 測試與驗收

### 後端

- 搜尋只回傳 `published` 店家。
- 地區結果與店家結果分組且受 `limit` 限制。
- 城市、行政區、料理與價格可組合查詢。
- 不含 bounds 的地圖查詢仍被拒絕。
- Provider 失敗不會寫入店家資料。

### 前端與 E2E

- 輸入地區後選取結果會移動地圖並顯示「搜尋此區域」。
- 輸入店家後選取結果會移動地圖並開啟預覽卡。
- 篩選條件可暫存、清除與套用；套用前不呼叫地圖查詢。
- 「搜尋此區域」使用最新 bounds 與 active filters。
- 搜尋／篩選失敗時保留既有標記。
- 手機與桌面面板不遮住 Footer、定位控制或預覽卡。
- 測試使用 API mock 或交易回滾，不留下資料庫測試資料。

## 7. 明確不包含

- 完整探索頁的全文搜尋、排序與 Top 3。
- 未發布、封存或外部候選店家。
- 使用者直接輸入地址後自動建立店家。
- 外部店家爬蟲或 Google Places 匯入。
- 以搜尋結果取代目前的地圖 bounds 查詢流程。
