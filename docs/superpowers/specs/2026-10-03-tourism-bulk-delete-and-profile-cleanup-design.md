# 觀光署批次刪除與個人頁精簡設計

## 目標

減少管理員逐筆刪除疑似重複資料時的等待，並精簡個人設定頁的登入裝置與內建頭貼呈現。

## 設計決策

### 疑似重複批次刪除

- 保留現有單筆永久刪除操作，另新增每筆來源資料的勾選框；左右兩側分別選取，避免誤把整組候選當成一筆刪除。
- 可跨目前列表頁的多組配對選取；批次按鈕顯示已選筆數。切換搜尋／縣市／行政區／資料類型或頁碼時清空選取，避免將隱藏項目一併刪除。
- 按批次刪除後先顯示確認視窗，列出筆數及所選名稱／地址；取消不送出請求。
- 新增管理員批次刪除 API，單一資料庫交易處理全部來源列與 tombstone。任一 ID 不存在或操作失敗時整批回滾；成功後前端只重新載入目前篩選結果一次。
- 來源列刪除後 tombstone 保留資料集與官方來源 ID，匯入繼續略過該 ID。已連結的 BiteMap 店家一律保留。

### 個人設定頁

- 移除整個「登入裝置」卡片，並移除頁面載入登入 session 列表的請求、狀態與撤銷裝置 handler；不變更後端 session API。
- 個人設定中的內建頭貼選項改為只顯示圖片，不顯示頭貼名稱文字；按鈕以頭貼名稱設定 `aria-label`，並保留選取外觀及 `aria-pressed`。
- 頭貼名稱仍由管理員資產資料維護，不改資料模型或後端 schema。

## 驗證

- 批次刪除成功時確認 API 一次接收多筆 ID、tombstone 與來源列同交易提交、一次刷新列表；失敗或取消不留下部分刪除。
- 確認在勾選、取消勾選、切換篩選／分頁時批次筆數正確，已連結 BiteMap 店家不受影響。
- 確認個人設定不再呼叫 `/me/sessions`、不顯示登入裝置卡片，且內建頭貼只有圖片但可由輔助科技辨識及選取。
- 執行相關前後端測試、lint 與 typecheck。
