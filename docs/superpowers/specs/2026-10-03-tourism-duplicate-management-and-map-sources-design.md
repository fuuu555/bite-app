# 觀光署疑似重複管理、地圖資料來源篩選與測試店家種子設計

## 目標

讓管理員更容易找出名稱略有差異的重複觀光署資料，安全地將不需要的官方來源資料排除；地圖可分別顯示 BiteMap 店家與觀光署資料；新 clone 的資料庫預設具有中原大學測試店，但管理員仍能永久刪除。

## 範圍與決策

1. 觀光署資料的疑似重複檢查與可還原的忽略狀態。
2. 地圖的 BiteMap／觀光署資料來源獨立開關。
3. 以 migration 預置中原大學測試店，並沿用店家管理的永久刪除能力。
4. 不自動合併、不改寫 BiteMap 店家資料，也不在每次應用程式啟動時重建已刪除的測試店。

## 觀光署資料疑似重複管理

### 候選比對

- 保留既有名稱／地址關鍵字搜尋，新增「疑似重複」清單檢視。
- 比對範圍為觀光署來源資料；名稱先作 Unicode 正規化、大小寫統一、移除空白與標點，再用 PostgreSQL `pg_trgm` 相似度找出名稱近似候選。
- 為正規化後的觀光署名稱建立 trigram GIN 索引；結果分頁載入，避免對整批來源資料產生未受限的配對清單。
- 地址相似度及座標距離作為佐證與排序因素；候選列顯示名稱、地址、資料集和可理解的比對原因。
- 候選只供管理員檢查；系統不自動判定主資料、不合併、不刪除。保留足夠測試案例驗證中英文括號、空白、標點與名稱附註等差異。

### 忽略與還原

- 在 `tourism_source_places` 加入可持久保存的忽略狀態。預設列表、地圖及疑似候選只包含未忽略資料；管理員可切換至「已忽略」列表並還原。
- 忽略僅作用於該筆觀光署來源資料。即使該來源列已連結 BiteMap 餐廳，也不刪除或封存 BiteMap 餐廳。
- 官方資料重新匯入時，沿用既有來源 ID 的忽略狀態；不因來源資料內容更新而自動恢復顯示。還原由管理員明確執行。
- 忽略確認文案說明該資料會從清單與地圖隱藏、匯入不會使其復活，並可從「已忽略」還原。

## 地圖資料來源篩選

- 「資料來源」區提供兩個互相獨立的開關：「BiteMap 店家」與「觀光署資料」，預設皆啟用。
- 移除既有「觀光署推薦」篩選及其 `officialOnly` 狀態，不保留會覆寫來源選擇的隱含模式。
- 關閉 BiteMap 店家時不發出餐廳地圖查詢，且隱藏 BiteMap 標記；關閉觀光署資料時不查詢官方地點，且隱藏官方圖層。重新開啟後依當前地圖範圍載入。
- 兩來源皆關閉時地圖保留底圖、不顯示店家標記，並顯示清楚提示。套用中的來源篩選要反映在篩選數量與標籤中，清除篩選則回復兩來源皆開啟。
- 來源關閉時若選取了相應圖層的地點，清除該選取狀態，避免資訊卡留下已隱藏地點。

## 中原大學測試店種子資料

- 目前資料庫中的店家資料：名稱「中原大學測試店」、地址「桃園市中壢區普忠里中北路200號」、座標 `24.9571129, 121.2425529`、台灣料理、價格區間 `under_200`、狀態 `published`。
- 新增一次性 Alembic migration 建立預置資料。以固定種子識別值與店名／地址防重檢查處理既有資料庫；料理分類依 slug 查找，不依賴各資料庫的隨機 UUID。
- 新 clone 執行 migration 後可取得此店家。已完成 migration 的資料庫不在應用程式啟動時重新 seed，因此管理員永久刪除後不會因重啟而復活；也不受觀光署匯入影響。
- 種子預設 `google_lookup_enabled=false`，避免測試店自動呼叫 Google Places；管理員仍可從現有店家管理流程開啟。
- 沿用店家管理目前的永久刪除 API 與確認流程，不額外建立測試店專用刪除機制。
- 探索頁目前的定位失敗備援仍使用中原大學座標；本次不調整該定位備援行為。

## 資料流與 API 變更

- 管理端觀光資料列表 API 支援疑似重複檢視及包含已忽略資料的管理模式；提供忽略與還原動作。
- 公開觀光地點查詢排除已忽略資料。
- 匯入服務更新來源欄位時保留管理員忽略狀態。
- 前端 `MapFilters` 移除 `officialOnly`，新增 `showBiteMapRestaurants`；保留 `showTourismData`。列表查詢、圖層能見度、載入訊息、active filter chip 與清除操作皆以兩個來源開關為準。

## 錯誤處理與安全

- 忽略或還原指定 ID 不存在時回傳 404；失敗時保留列表狀態並顯示操作錯誤。
- 疑似配對演算法只呈現候選，不因分數高就採取寫入或刪除。
- 種子 migration 可在有相同既存記錄的資料庫安全重複檢查；不修改管理員後續編輯過的欄位。
- 地圖來源查詢彼此獨立；一個來源查詢失敗不應阻止另一個已啟用來源正常顯示。

## 驗證

- 後端測試名稱正規化與相似候選、忽略／還原、重複匯入仍保留忽略狀態，以及公開地圖不回傳忽略資料。
- 前端測試預設兩來源皆開啟、兩個開關彼此獨立、單一來源關閉時不查詢該來源、兩來源關閉提示、篩選計數／標籤與清除行為。
- Migration 驗證新資料庫能建立測試店，既有同名同址資料不會重複，且刪除後應用程式重啟不會重建。
- 手動驗證管理頁疑似重複對照、忽略／還原、官方重新匯入後狀態保持，以及已連結 BiteMap 店家不受影響。
