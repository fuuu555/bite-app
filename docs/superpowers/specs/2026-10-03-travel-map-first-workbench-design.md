# BiteMap AI 個人化旅遊：地圖優先工作台設計

日期：2026-10-03  
狀態：已由使用者確認 A「地圖優先工作台」方向

## 1. 目標

重新整理地圖頁與 `/travel` 的 AI 個人化旅遊入口及版面，讓使用者先看到地圖與行程位置關係，再處理推薦與草稿。既有定位、快捷推薦、自然語言規劃、加入行程、本機保存及 BiteMap 內部路線功能維持不變。

本次必須解決三個問題：

1. 地圖頁缺少顯眼的「AI 規劃全台旅遊行程」入口。
2. `/travel` 的品牌與主要操作不夠醒目。
3. 現有桌面三欄過窄，推薦卡片垂直堆疊過長，地圖、推薦與行程草稿彼此爭奪空間。

## 2. 地圖頁入口

- 在公開地圖頁桌面版右上控制區加入高對比的「AI 規劃全台行程」按鈕，連到 `/travel`。
- 按鈕使用 BiteMap 珊瑚橘主色、路線或閃光圖示及清楚的前進提示，使其與白色搜尋列及行程摘要形成明確層級。
- 入口不得遮住搜尋列、篩選器、行程摘要、地圖縮放控制或店家預覽卡。
- 手機版入口放在地圖頂部搜尋控制區下方，以緊湊橫幅呈現；有預覽卡或展開行程摘要時，仍不得遮住主要操作。
- 探索頁原有 `/travel` 入口保留並提高按鈕感，讓探索與地圖都能進入 AI 旅遊流程。

## 3. `/travel` 資訊架構

### 3.1 頁首與主要命令

- 頁首改為緊湊的品牌區，不再使用佔據大量垂直空間的超大標題。
- 清楚顯示「AI 個人化旅遊」與「規劃全台旅遊行程」，並保留資料可追溯說明。
- 自然語言輸入與「開始規劃」是頁面最醒目的主要操作；按鈕使用主色，載入時保留現有停用及文字狀態。

### 3.2 搜尋條件面板

- 桌面版左側為搜尋控制面板，包含目前位置／縣市、四個快捷功能及主要條件。
- 目前位置、快捷功能與開始規劃維持直接可見。
- 行程時間、搜尋距離、交通方式、興趣、飲食及住宿等進階條件以緊湊排列或可收合區呈現，避免表單高度超過地圖。
- 錯誤訊息仍在控制面板內就近顯示，不使用瀏覽器原生警告視窗。

### 3.3 地圖主畫面

- 地圖是工作台最大且優先的內容，位於右側上方。
- AI 推薦完成後，地圖顯示推薦地點；使用者按「在地圖顯示路線」後，改為顯示行程草稿順序標記與內部連線。
- 草稿路線狀態顯示「我的行程路線」標章；重新推薦後回到推薦地圖狀態。
- 地圖保留 MapLibre 縮放、標記、來源資料與現有視覺路線邏輯，不新增 Google Maps 或道路導航 API。

### 3.4 推薦與行程草稿

- 大地圖下方使用雙欄：左側為推薦結果，右側為我的行程草稿。
- 推薦結果改為緊湊橫列，每列顯示順序、類型、名稱、距離、來源及加入狀態；不得讓每個地點形成大面積直式卡片。
- 推薦標題、摘要與「重新推薦」位於清單頂部；替換地點置於推薦清單後方，但沿用同一緊湊元件。
- 行程草稿固定靠近推薦清單，列出已加入地點、類型、順序及移除操作。
- 草稿清單超過可視高度時只在面板內捲動，不把整頁向下撐長。
- 至少兩個具有效座標的地點時啟用「在地圖顯示路線」；少於兩個時顯示明確原因。
- 「管理完整行程」繼續連至 `/itinerary`。

## 4. 響應式行為

### 桌面（大於 1100px）

- 工作台為左側控制面板、右側主內容。
- 右側主內容先是大地圖，下面是推薦與草稿雙欄。
- 控制面板可 sticky，但不得造成左右欄互相截斷。

### 平板（761px–1100px）

- 頁面改成單欄：主要命令、條件、地圖、推薦與草稿依序呈現。
- 草稿緊接地圖或推薦區，不落到所有推薦項目之後。

### 手機（760px 以下）

- 頁首、輸入與快捷操作垂直排列。
- 地圖維持足夠可操作高度。
- 行程草稿沿用固定底部摘要，可展開為具內部捲動的面板，並避開既有 Footer 導覽。
- 推薦列改為單欄，但資訊與加入按鈕保持同一視線範圍。

## 5. 元件與程式邊界

- `public-map-page.tsx`：新增 `/travel` 入口，不改動地圖查詢及標記資料流程。
- `itinerary-page.tsx`：重組頁面區塊及狀態呈現，不改動既有 API payload、定位、推薦、加入／移除及路線狀態。
- `itinerary-draft-panel.tsx`：保留草稿責任，調整為新雙欄與響應式版面可重用的面板。
- 推薦地點的顯示元件改為緊湊列，但仍使用既有 `isPlaceInItinerary`、`addStop` 與來源標籤。
- `itinerary-map.tsx`：沿用現有 MapLibre 與草稿路線 props；本次不修改道路幾何或外部導航。
- 樣式延續現有 `web.css`、`desktop.css`、`mobile.css`，不引入新 UI 套件或另一套設計系統。

## 6. 互動與狀態

- 初始狀態：地圖區顯示具體引導，快捷功能與自然語言輸入可立即操作。
- 載入狀態：開始規劃按鈕顯示「正在規劃…」並停用重複提交。
- 結果狀態：推薦、地圖與可替換地點使用相同資料來源。
- 草稿路線狀態：地圖依草稿順序顯示；移除地點後同步更新，少於兩點則自動停止顯示路線。
- 空狀態：沒有推薦時提供調整距離、縣市或偏好的建議。
- 錯誤狀態：API、定位或本機保存失敗時保留目前資料並顯示可閱讀訊息。

## 7. 可及性與視覺要求

- 所有按鈕維持鍵盤焦點、`aria-pressed`、`aria-expanded` 或可辨識標籤。
- 主色按鈕與文字需符合清楚對比；資料來源不得只用顏色辨識。
- 地圖、控制面板、推薦與草稿之間建立明確視覺層級，避免每個區塊都使用同等重量的白色卡片與陰影。
- 沿用 BiteMap 暖白、深墨綠、珊瑚橘與觀光資料綠，不新增紫藍 AI 漸層。

## 8. 驗收條件

1. 地圖頁桌面與手機都能清楚看到前往 `/travel` 的 AI 規劃入口。
2. `/travel` 首屏能同時看到主要規劃操作與地圖，不需先滑過完整表單。
3. 桌面推薦結果不再與地圖、草稿形成三個狹窄並排欄。
4. 推薦資料增加時，草稿仍保持在地圖附近且可獨立捲動。
5. 「在地圖顯示路線」會在 `/travel` 目前的 MapLibre 地圖顯示草稿順序連線。
6. 原有快捷功能、定位、重新推薦、加入／移除行程、`/itinerary` 連結及本機保存維持可用。
7. TypeScript、ESLint 與格式檢查通過；以瀏覽器檢查桌面、平板及手機主要流程。本次不新增或執行測試。

## 9. 不在本次範圍

- Google Maps 導航、道路 polyline、即時交通或新的外部 API Key。
- 修改推薦演算法、資料集匯入或後端 API schema。
- 行程登入帳號同步、跨使用者分享或預訂付款。
