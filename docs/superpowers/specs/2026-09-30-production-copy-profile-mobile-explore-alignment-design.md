# 正式產品文案、個人頁手機版與探索頁對齊設計

## 目標

把目前使用者端介面中帶有開發說明、骨架狀態或內部規則的文案移除，讓產品以正式服務的語氣呈現；同時改善個人頁手機版操作與探索頁卡片對齊。

本次是既有視覺語言下的精簡與排版修正，不更換 BiteMap 的暖白、珊瑚色、深青文字、圓角與 Tabler 圖示系統。

## 1. 正式產品文案

使用者頁面不顯示下列內部狀態：

- 「骨架」、「暫定」、「尚未啟用」、「資料來源尚未定案」等開發說明。
- 排序權重、推薦規則、資料管線或後續階段等實作資訊。
- 重複解釋頁面用途、但不協助使用者完成操作的副標與狀態文字。

探索頁調整：

- 保留「今天想吃什麼？」主標題，移除其下方說明句。
- 「本週 Top 3 必吃」保留標題，移除排序規則說明與「搜尋後更新」。
- 「完整搜尋結果」保留標題與排序控制，移除重複說明句。
- 將「穩定排序（骨架）」改為正式產品名稱「推薦排序」。

其他使用者頁面同步移除同類開發文案，但保留下列必要內容：

- 可操作的空狀態與下一步按鈕。
- 錯誤原因與恢復方式。
- 權限、資料安全或會影響操作結果的必要提示。

管理後台可保留管理員需要的操作說明；不向一般使用者暴露開發階段資訊。

## 2. 個人頁與登出

- 刪除個人卡片中的「在餐廳頁留下留言，慢慢建立自己的美食紀錄。」區塊。
- 登出入口從個人設定頁移除，改放在個人頁全部內容的最下方。
- 登出使用次要危險操作樣式，與編輯個人資料、留言、收藏等主要操作分離。
- 登出仍呼叫既有登出 API，成功後返回登入頁；不改變驗證或 Session 規則。

### 手機版個人頁

- 身份卡改為較緊湊的橫向排列：頭像、名稱、自我介紹與標籤形成同一資訊群組。
- 「編輯個人資料」保持明確可觸控，但不與頁面主標題爭奪視覺焦點。
- 公開資料／美食留言／收藏分頁在窄螢幕維持單列可操作，文字與數字不換成兩行。
- 內容列表使用一致的內距、分隔與觸控高度；避免巢狀卡片和多層陰影。
- 登出區位於內容與留白之後，避免誤觸，也不固定在畫面底部。

## 3. 管理員店家地址提示

地址欄 placeholder 改為：

`例：台北市信義區忠孝東路五段159號（不要輸入樓層）`

既有樓層偵測與警告保留。placeholder 用於輸入前提醒，警告則處理已輸入「一樓／5 樓」等內容的情況。

## 4. 探索頁對齊

Top 3 卡片使用一致的版面骨架：

- 卡片使用相同高度並採直向 flex/grid 排版。
- 圖片區使用固定比例與一致高度；無照片狀態占用相同空間。
- 名稱、地址、標籤與評價區使用一致的間距。
- 「查看餐廳」固定在卡片內容底部，所有卡片按鈕基線一致。
- 桌面版多欄卡片頂端與底端對齊；手機版回到單欄自然高度，不製造過多空白。

完整搜尋結果的圖片、文字與操作欄位也維持垂直置中，避免有照片和無照片項目高低錯位。

## 5. 響應式與無障礙

- 互動按鈕維持至少 44px 觸控高度。
- 分頁、登出與探索卡片連結保留鍵盤 focus 狀態。
- 文字移除後重新檢查 heading 階層，避免只靠副標維持結構。
- 以桌面與手機尺寸各檢查一次：個人頁、探索頁、個人設定頁與管理員店家編輯頁。

## 6. 驗收條件

- 使用者端不再顯示「骨架」、「尚未啟用」、「資料來源尚未定案」等內部產品文案。
- 個人卡片不再顯示指定美食紀錄說明句。
- 個人設定頁沒有登出按鈕；個人頁最下方可正常登出。
- 手機個人頁身份、分頁、內容與登出操作不重疊、不溢出且觸控順暢。
- 地址欄在空白時直接提醒不要輸入樓層，既有樓層警告仍有效。
- 探索頁同列卡片圖片區、資訊區與操作基線一致。
- Formatter、lint、TypeScript、相關測試與 production build 通過。
