# Stage 7 私人約飯條件設計

## Scope

為私人約飯加入簡單的條件標示：`限男性` 或 `限女性`。此條件是發起人提供給申請者參考的飯局規則，不代表系統驗證過申請者的性別，也不新增個人性別欄位。

## Confirmed behaviour

- 建立私人約飯時，發起人可選擇 `限男性`、`限女性`，或不設定條件。
- 公開約飯不顯示或接受私人條件。
- 私人約飯列表、詳情與申請畫面顯示條件標籤。
- 申請者仍可送出申請，不由系統自動判斷或攔截。
- 發起人依現有個人資料自行審核並接受或拒絕申請。
- 不新增使用者性別欄位，不把自填資料當成已驗證身分。
- 使用者檢舉功能不在本次實作，保留為後續社交安全工作。

## Data and API

- 在 `meal_events` 新增可為空的 `private_condition` 欄位，允許值為 `male_only`、`female_only` 或 `NULL`。
- 只有 `visibility = private` 時可設定非空條件；公開約飯必須為 `NULL`。
- `MealCreateRequest`、`MealResponse` 與前端 API 型別同步新增此欄位。
- 新增可逆 Alembic migration，既有資料預設為 `NULL`。

## Frontend

- 私人約飯建立表單顯示條件選項：不限、限男性、限女性。
- 公開約飯建立流程不顯示條件選項。
- 約飯卡片與詳情頁顯示已設定的條件標籤。
- 申請按鈕不因條件自動停用，申請結果仍由既有發起人審核流程處理。

## Validation and tests

- Backend 驗證公開約飯不能帶私人條件。
- Backend 驗證私人約飯可使用兩種條件或不設定條件。
- API 回應正確帶出私人條件，申請流程不因條件而自動拒絕。
- Frontend 測試建立草稿、解析條件與條件標籤顯示。
- 既有 Stage 7 公開／私人約飯、申請、審核與投票測試維持通過。

## Out of scope

- 使用者性別欄位、身分驗證或自動性別判定。
- 檢舉資料模型、檢舉 API、審核後台與處置流程。
- 修改既有私人約飯成員審核權限與投票規則。
